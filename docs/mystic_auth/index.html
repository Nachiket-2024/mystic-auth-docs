Documentation

Documentation for this full-stack authentication and PBAC template, organized by feature and runtime ownership. The structure mirrors the code layout under backend/mystic_auth/<domain>/ and frontend/src/mystic_auth/<domain>/.

This is the template's own reference documentation, belonging to upstream and not yours to edit. Your own project's docs go in docs/app/ instead, so they never conflict with a future scripts/upstream-sync/sync-upstream.sh run. See Using This Repository as a Template: the app/ + mystic_auth/ split for the full reasoning.

Read the docs in this order if you are new to the repository:

  1. System Overview
  2. Authentication Overview
  3. Authorization Architecture
  4. Deployment Guide
  5. Testing Overview

Documentation conventions​

  • Documentation Style: page structure, numbered procedure style, Mermaid label rules, code reference conventions, and tutorial section format.

Architecture​

  • System Overview: whole-stack component diagram, why the stack is split this way, request lifecycle
  • Backend Architecture: backend/mystic_auth/ module layout, request pipeline, middleware
  • Frontend Architecture: frontend/src/mystic_auth/ module layout, state management, routing, theming
  • Implementation Coverage Map: where each major backend, frontend, test, script, Docker, and env directory is documented, including important edge cases

Authentication​

  • Authentication Overview: JWT/cookie mechanics, refresh-token rotation, current-session lookups, and links to every flow below
  • Signup and Email Verification: account creation, verification token issue/redeem, resend
  • Login: rate limiting, brute-force lockout, timing-attack resistance
  • Logout and Logout-All: single-device vs. whole-account session termination, idempotency
  • Password Reset and Password Change: forgot-password flow, self-service and admin password change
  • Session Management: active-session tracking, refresh-token rotation mirror, dashboard card behavior, revoke edge cases
  • Account Deletion and Purge: self-service delete (password re-confirm and OAuth email-confirm paths), admin delete/reactivate/purge, and the scheduled grace-period purge job
  • OAuth2 / PKCE: Google OAuth2 login flow, PKCE code-challenge mechanics, CSRF state protection
  • System Superuser: Bootstrapping and Promotion: create_system_user.py's full behavior, covering fresh creation, promoting an existing account, and the Google-only-account special case

Authorization (PBAC)​

  • Architecture Overview: request flow, component responsibilities, integration points
  • Policy JSON Examples: basic, conditioned, superuser, and self-service policies
  • RBAC Quickstart: plain role-shaped access (no conditions) using the same policies, for projects that don't need PBAC's full generality
  • Common Patterns: modeling common access shapes (e.g. org-chart/company-group hierarchies) on top of PBAC's existing condition types
  • Condition Schema Reference: every supported condition type, field-by-field
  • Adding New Permissions: extending the action vocabulary
  • Adding New Condition Handlers: extending the condition framework
  • Writing and Testing Policies: policy lifecycle, local testing, unit test patterns
  • Operational Troubleshooting Guide: common issues, logging, Redis/DB debugging

Database​

  • Database Design: schema, foreign keys, account lifecycle (soft delete/purge/reactivate)

API​

  • API Reference: route inventory grouped by domain, request/response shapes, auth requirements

Background Email Delivery​

  • Background Email Delivery: Procrastinate worker setup, Postgres-backed job queue, backoff retries, failure handling

Security​

  • Security Decisions: index of the why behind non-obvious security choices, plus known accepted gaps, split into Auth & Session, Infrastructure, and Product
  • Security Hardening: rate limiting, lockout, security headers, CORS, cookie flags, consolidated
  • Rate Limits: the generic per-IP/per-account limiter, brute-force lockout, and the Rate Limit Dashboard (GET /rate-limits/, frontend/src/mystic_auth/rate_limits/) an admin uses to view and reset active limits
  • SECURITY.md: how to report a vulnerability privately (not via a public GitHub Issue)

Error Monitoring​

  • Error Monitoring: enabled-by-default backend/frontend error reporting via the Sentry SDK protocol; self-hosted Bugsink quickstart and what gets reported

Geolocation​

Appearance​

Legal​

  • Legal Documents and Signup Consent: the in-app Privacy Policy and Terms of Service pages, the signup consent notice (not a gating checkbox), and what an operator needs to edit before shipping to real users

  • Tutorial: Adding a New Language: step-by-step walkthrough of adding a new language

  • Testing Overview: backend pytest suites, frontend vitest suites, coverage state, how to run

Docker​

CI/CD​

  • CI/CD Overview: GitHub Actions workflow, jobs, gaps

Deployment​

  • Deployment Guide: mode chooser and links to focused deployment references
  • Environment and Runtime Configuration: env file selection, build-time vs runtime settings, production review checklist
  • Frontend and Backend Routing: same-origin nginx proxying, trusted proxy IPs, and SPA/API route collisions
  • Migrations and Backups: Alembic service behavior, backup scripts, scheduled backup sidecar, restore discipline
  • Production Host Requirements: shutdown behavior, service responsibilities, host requirements, deployment limitations
  • Dev Deployment: local development, hot reload, no TLS
  • Local-Prod Deployment: self-hosted production image shape exposed via a free tunnel, no public server needed, with Cloudflare Quick Tunnel, Cloudflare Named Tunnel, ngrok, and Tailscale Funnel walkthroughs

Concerns, Limitations & Technical Debt​

Project Story​

  • Project Story: where this template came from and how its architecture settled into its current shape
  • How It Evolved: the commit-by-commit log, straight from the commit history
  • The Tools That Built It: the workflows that actually did the work, from manual ChatGPT + VSCode through Claude Code and the first Codex pass

Using This as a Template​

  • Template Usage Guide: for anyone cloning this repo as a starting point for their own auth+PBAC project, covering quickstart, environment configuration, renaming the app, backend customization, OAuth/email setup, adding permissions and protecting routes, replacing the frontend, deployment
  • Frontend Customization: theme, pages, routing, state, and the shared-chrome extension points (nav items, navbar content, command palette search, audit log filters)
  • Worked Example: Adding a New Domain, End to End: a copy-and-rename starting point, covering model, schema, router, migration, policy, frontend page, route, and nav link, wired together for one fake domain
  • Staying in Sync with Upstream Template Updates: pulling fixes/features from the original template into your own diverged project, step by step, plus a worked conflict-resolution example

Who this is for​

Anyone adding a new protected endpoint, a new permission, a new condition type, or a new policy to this template; anyone integrating a new frontend feature against the API; anyone debugging why an authorization decision or a request came back the way it did; or anyone new to the codebase who needs the system-wide picture before touching auth, authorization, or infrastructure code.

Source of truth​

This documentation describes the code as it exists in backend/mystic_auth/ and frontend/src/mystic_auth/ at the time of writing. If something here disagrees with the code, the code wins.
