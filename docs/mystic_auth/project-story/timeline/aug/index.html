How It Evolved: August 2025

Commit 1: 18 August, 2025​

870b169: "Initial Commit"

  • A bare FastAPI skeleton: backend/app/core/settings.py, an early security.py (password hashing/JWT groundwork), requirements.txt, and empty package stubs.
  • No routes yet.

8 files changed · +344/-0 lines

Commit 2: 19 August, 2025​

4d8382a: "Modular ,secure Auth logic written along with table and role based login setup"

  • An admin model/schema/CRUD added: the first role-based user table.
  • auth_logic/: login, logout, OAuth2-login, password-reset, and signup business logic each split into their own file.
  • auth_routes/auth_routes.py: the first real auth route file, plus per-flow Pydantic schemas under auth_schemas/.
  • auth_security/: login_protection_service.py and rate_limiter_service.py, brute-force and rate-limit protection sketched in from the start, not bolted on later.
  • auth_services/auth_service.py: the core service tying it together.

59 files changed · +1,968/-137 lines

Commit 3: 20 August, 2025​

4840532: "Auth + OAuth, logic and flow improved along with Rate limiting and brute force protection"

  • account_verification_logic.py and account_verification_service.py added: email verification split out as its own flow.
  • client_ip_service.py added: the first attempt at extracting the real client IP (relevant later once X-Forwarded-For spoofing became a real concern).
  • jwt_service.py, oauth_service.py, password_reset_service.py, password_service.py, and refresh_token_service.py all reworked.
  • redis/cache.py and redis/tokens.py removed: an early Redis token module was dropped here, before Redis-only sessions actually landed a month later.
  • Security concerns became obvious while building the foundation, not because they were planned upfront.

31 files changed · +948/-517 lines

Commit 4: 21 August, 2025​

df8c656: "Refactored, modularised Auth logic ,flow and role tables with standard security practices"

  • The auth_logic//auth_routes//auth_schemas//auth_services/ split from two days ago was scrapped entirely in favor of one folder per flow.
  • auth/login/ (login_handler.py, login_schema.py, login_service.py) and auth/logout/logout_handler.py appear here: the pattern the rest of the backend would follow from now on.
  • api/auth_routes/auth_routes.py was rewritten from scratch (207 lines) to replace the old 111-line version.
  • admin_table//admin_token_table/ were split out of the single admin/ folder.

79 files changed · +1,899/-975 lines

Commit 5: 21 August, 2025​

db2827b: "Added Logout from all devices endpoint with proper logic and flow"

  • auth/logout/logout_all_handler.py added (59 lines, new), wired into auth_routes.py.
  • jwt_service.py and refresh_token_service.py both grew substantially in the same commit to support it: a logout-all has to actually invalidate every issued refresh token, not just the current one.

8 files changed · +177/-18 lines

Commit 6: 22 August, 2025​

5be5b07: "Created Role based routes and main.py file"

  • main.py written for the first time (100 lines): the app finally had a real entrypoint.
  • access_control-adjacent admin_logic/ (create/delete/get/get-all/update) CRUD handlers added for the admin role.
  • role1/role1_logic/ and role2/role2_logic/ added, mirroring the admin CRUD exactly: this is where the three-tier admin/role1/role2 role system took shape, each with its own full CRUD and its own route file (api/role_routes/admin_routes.py, role1_routes.py, role2_routes.py).
  • auth/utils/role_checker.py added: the first permission-checking dependency.

29 files changed · +1,060/-72 lines

Commit 7: 22 August, 2025​

9b889fc: "Modified role routes to a generic structure with permission injections ;Alembic initial migration done"

  • The three separate admin_routes.py/role1_routes.py/role2_routes.py files from yesterday were deleted and replaced by one generic role_routes.py (157 lines) parameterized by permission instead of duplicated per role.
  • A new access_control/ package (role_checker.py, role_permissions.py, role_tables.py) replaced the scattered admin_logic/ CRUD files.
  • Alembic scaffolding (alembic.ini, env.py, script.py.mako) added for the first time.

56 files changed · +600/-996 lines

Commit 8: 23 August, 2025​

92bc5a8: "Corrected relative imports, updated libraries ; frontend creation started"

  • Backend: minor import fixes to settings.py, connection.py, redis/client.py.
  • Frontend created from scratch: a full Vite + React + TypeScript + Tailwind scaffold (package.json, tailwind.config.cjs, tsconfig*.json, vite.config.ts, App.tsx, main.tsx, placeholder pages/About.tsx/Home.tsx).
  • This is the actual frontend bootstrap: everything downstream in the frontend builds on this one commit.

27 files changed · +4,760/-16 lines

Commit 9: 23 August, 2025​

145a964: "Typescript + React basic set up for Frontend"

  • core/settings.ts added.
  • The first Redux Toolkit slice appeared (slices/auth/signup/signup_slice.ts plus signup_types.ts), establishing the slice-per-flow pattern the rest of the frontend auth code would follow.

12 files changed · +527/-35 lines

Commit 10: 26 August, 2025​

fe433a6: "Tailwind CSS replaced by normal CSS"

  • postcss.config.cjs and tailwind.config.js deleted, index.css rewritten by hand (72 lines).
  • App.tsx and main.tsx rewritten to match, the placeholder About/Home pages removed.
  • store/store.ts introduced as the real Redux store (replacing the placeholder store/index.ts), alongside a new login_slice.ts.

21 files changed · +463/-1,300 lines

Commit 11: 26 August, 2025​

36f7627: "Modular slice ,types ,button ,form files added ;store.ts updated"

  • This is where the frontend's per-flow folder convention was established: auth/login/, auth/logout/, auth/oauth2/, auth/password_reset_confirm/, auth/password_reset_request/, auth/signup/, and auth/verify_account/ each got their own form component, Redux slice, and types file.
  • Mirrors the backend's own per-flow split from a few days earlier.

23 files changed · +1,147/-57 lines

Commit 12: 27 August, 2025​

2802d0d: "Auth route pages created and added in App.tsx"

  • Each flow from the previous commit got a routed page component on top of its form: LoginPage.tsx, PasswordResetConfirmPage.tsx, PasswordResetRequestPage.tsx, SignupPage.tsx, VerifyAccountPage.tsx.
  • Before this, the forms existed but weren't reachable by URL.

10 files changed · +252/-74 lines

Commit 13: 28 August, 2025​

c15a349: "Centralised all axios api calls in api folder and updated files to use the same"

  • api/auth_api.ts (41 lines, every backend call in one place) and api/axiosInstance.ts (14 lines, the shared client) added.
  • Every existing slice (login, logout, oauth2, password-reset confirm/request, signup, verify-account) rewritten to call through them instead of hitting axios directly: the frontend's first consistent shape.

10 files changed · +179/-95 lines

Commit 14: 30 August, 2025​

6a46818: "Corrected frontend imports and added Tailwind CSS"

  • A new tailwind.css file, and tsconfig/vite.config.ts updated to support it.
  • Small one- or two-line import-path fixes rippling across nearly every existing auth flow file.

21 files changed · +819/-316 lines

Commit 15: 31 August, 2025​

61b88fe: "Added HTTP-only cookie for tokens in auth ,token routes"

  • api/auth_routes/auth_routes.py and refresh_token_routes.py reworked so the backend sets tokens via httpOnly cookies instead of returning them in the JSON response body.
  • App.tsx updated to stop reading tokens out of that body.

3 files changed · +113/-45 lines

Commit 16: 31 August, 2025​

159bd06: "Basic Oauth2 flow works now with integration of frontend, backend, redis ,postgresql"

  • frontend/src/auth/ProtectedRoute.tsx appeared for the first time (43 lines, the first real route guard).
  • Fixes to oauth2_login_handler.py, oauth2_service.py, and the (now relocated) security/rate_limiter_service.py.
  • The first time all the moving pieces (frontend, backend, Redis, Postgres) talked to each other.

13 files changed · +107/-31 lines
